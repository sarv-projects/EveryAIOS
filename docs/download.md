## Verify (once a release exists)

`SHA256SUMS` is generated by
`node scripts/gen-release-surface.mjs --artifacts <bundle-dir>` over the
artifacts the release job just produced — never hand-written.

```
sha256sum -c SHA256SUMS              # Linux/macOS
certutil -hashfile <file> SHA256     # Windows
```

1. **Checksum** each downloaded file against the `SHA256SUMS` from the same release.
2. **Signature** — released Windows builds are Authenticode-signed; confirm the signer
   is `EveryAIOS` and the timestamp is present (right-click → Properties →
   Digital Signatures). Custody, renewal and revocation are in
   [`docs/signing.md`](signing.md).
3. **Updater trust** — the in-app updater accepts only manifests signed by the
   minisign public key pinned in `src-tauri/tauri.conf.json`; the key's
   custody and rotation rules are in [`docs/updating.md`](updating.md) §1 and
   `docs/signing.md` §3.

> Until the Authenticode certificate is procured, the release job **fails
> loudly** rather than publishing an unsigned installer (`P70.B1`). If a build
> has no certificate, the correct outcome is no download, not an unverified
> one.

## Not yet

Stated plainly, because the alternative is a page that implies more than the
build delivers:

- **Windows is not yet qualified on a real host.** The acceptance pass
  (`P70.E8`) has not been executed; the clean-machine install test (`P70.E9`)
  and the live soaks are open. `node scripts/release-qualify.mjs` prints them as
  `BLOCKED` in every run.
- **No live update has ever been served.** The updater, channels and rollout
  policy are implemented and gated, but no hosted endpoint exists yet.
- **macOS/Linux desktop installers are not planned for v1** — not "coming
  soon".
