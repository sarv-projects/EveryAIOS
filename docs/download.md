# Download and verify (P70.F3 — current release v0.1.0)

> This page is the download contract. It names the current release, the files
> that ship, how to verify them, and what the build does **not** yet claim.
> `scripts/gen-release-surface.mjs --check` fails the docs-sync job when the
> version here drifts from `src-tauri/tauri.conf.json`, so a stale page is a red
> build rather than a stale page.

## Current release

**v0.1.0** — Windows x64 and Windows arm64.

| File | Platform | Notes |
|---|---|---|
| `EveryAIOS_0.1.0_x64-setup.exe` | Windows 10/11 x64 | NSIS installer, per-user, no elevation |
| `EveryAIOS_0.1.0_arm64-setup.exe` | Windows 10/11 ARM64 | NSIS installer, per-user, no elevation |
| `EveryAIOS_0.1.0_x64_en-US.msi` | Windows 10/11 x64 | WiX installer (pinned upgrade code) |
| `EveryAIOS_0.1.0_arm64_en-US.msi` | Windows 10/11 ARM64 | WiX installer (pinned upgrade code) |
| `SHA256SUMS` | — | checksums for every artifact above |
| `latest.json` + `.sig` | — | the updater manifest and its minisign signature |

**No macOS or native Linux desktop artifact is published.** Both are declared
out of v1 scope in [`SUPPORT-MATRIX.md`](../SUPPORT-MATRIX.md); WSL2 is
supported as a **host for Linux-native agents**, not as a place to run the
cockpit.

## Checksums

`SHA256SUMS` is in every release, generated by
`node scripts/gen-release-surface.mjs --artifacts <bundle-dir>` over the
artifacts the release job just produced — never hand-written.

```
sha256sum -c SHA256SUMS        # Linux/macOS
certutil -hashfile <file> SHA256   # Windows
```

## Verify

1. **Checksum** each file against `SHA256SUMS` (above).
2. **Signature** — Windows builds are Authenticode-signed; confirm the signer
   is `EveryAIOS` and the timestamp is present (right-click → Properties →
   Digital Signatures). Custody, renewal and revocation are in
   [`docs/signing.md`](signing.md).
3. **Updater trust** — the in-app updater accepts only manifests signed by the
   minisign public key pinned in `src-tauri/tauri.conf.json`; the key's
   custody and rotation rules are in [`docs/updating.md`](updating.md) §1 and
   `docs/signing.md` §3.

> Until the Authenticode certificate is procured, the release job **fails
> loudly** rather than publishing an unsigned installer (`P70.B1`). If a build
> has no certificate, the correct outcome is no download, not an unverified
> one.

## Not yet

Stated plainly, because the alternative is a page that implies more than the
build delivers:

- **Windows is not yet qualified on a real host.** The acceptance pass
  (`P70.E8`) has not been executed; the clean-machine install test (`P70.E9`)
  and the live soaks are open. `node scripts/release-qualify.mjs` prints them as
  `BLOCKED` in every run.
- **No live update has ever been served.** The updater, channels and rollout
  policy are implemented and gated, but no hosted endpoint exists yet.
- **macOS/Linux desktop installers are not planned for v1** — not "coming
  soon".
